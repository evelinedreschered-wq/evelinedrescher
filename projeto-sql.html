SQL — Consolidação e análise de custos

Desenvolvimento de uma View em Oracle SQL para consolidar informações de projetos, solicitações, amostras, análises, planejamento e custos em uma estrutura única para análise e geração de informações.

Problema

As informações necessárias para análises de custos e planejamento estavam distribuídas em diferentes tabelas do banco de dados.

Para obter uma visão consolidada, era necessário relacionar informações de projetos, solicitações, amostras, análises, códigos de custo e valores financeiros. Além disso, diferentes cenários de registros precisavam receber tratamentos específicos.

O desafio foi transformar informações distribuídas em uma estrutura única, organizada e reutilizável para análises.

Objetivo

Desenvolver uma View SQL capaz de consolidar informações provenientes de diferentes tabelas em uma única estrutura, permitindo análises de custos e planejamento de forma mais organizada.

  • Relacionar informações de projetos e solicitações;
  • Consolidar dados de amostras e análises;
  • Relacionar informações de planejamento e custos;
  • Tratar diferentes cenários de registros;
  • Disponibilizar uma estrutura reutilizável para relatórios e análises.

Desenvolvimento

A solução utiliza recursos de Oracle SQL para construir a View ANALYTICAL_COST_PLAN_QUOTE. A consulta foi estruturada em blocos para tratar os dados, realizar os relacionamentos e consolidar os diferentes cenários.

1. Seleção e organização dos dados

O primeiro bloco define as informações que serão disponibilizadas pela View. São selecionados dados de projeto, programa, subprojeto, solicitação, clientes, amostra, análise, data, laboratório, planejamento e custos.

Trecho da consulta:
SELECT
    CASE WHEN o.about_entity IS NULL THEN ... ELSE o.about_entity END AS project_code,
    o.template AS programa,
    ...
    BFC.TOTAL_COST AS total_cost
FROM ...

2. Tratamento das informações textuais

Os campos textuais recebem tratamento para remover tabulações, quebras de linha, aspas e ponto e vírgula. Isso padroniza os valores que serão disponibilizados no resultado.

Trecho da consulta:
replace(
    replace(
        replace(
            REPLACE(o.project_name, CHR(9), '_'),
            chr(13), ''
        ),
        chr(34), ''
    ),
    ';', '_'
) AS project

3. Regra de negócio com CASE WHEN

O CASE WHEN define o valor de project_code. Quando about_entity está vazio, a consulta utiliza project_code após o tratamento dos caracteres; caso contrário, utiliza about_entity.

Trecho da consulta:
CASE
    WHEN o.about_entity IS NULL
    THEN replace(
        replace(REPLACE(o.project_code, CHR(9), '_'), chr(13), ''),
        ';', '_'
    )
    ELSE o.about_entity
END AS project_code

4. Subconsultas

Subconsultas são utilizadas para buscar informações complementares, como nomes dos usuários responsáveis pela solicitação e códigos de análise associados ao código de custo e à amostra.

Trecho da consulta:
(select full_name
   from lims_users
  where user_name = o.created_by) as solicitante,

(select full_name
   from lims_users
  where user_name = o.requester_2) as client_1,

(select analysis
   from test
  where cost_code = tbl2.cost_code
    and sample_number = TBL2.SAMPLE_ID
    and rownum = 1) as analysis_code

5. Cálculo do plano de réplicas

O campo rep_plan é calculado a partir dos resultados associados ao teste. A consulta considera os registros com status N, E e M, conta réplicas distintas e utiliza MAX para consolidar o resultado por nome.

Trecho da consulta:
(select max(count(distinct(replicate_count)))
    from result
   where test_number = t.test_number
     and status in ('N','E','M')
  group by name) as rep_plan

6. Relacionamento entre tabelas com JOIN

A consulta utiliza INNER JOIN para relacionamentos necessários e LEFT JOIN para trazer informações financeiras quando disponíveis. A tabela VERSIONS também é utilizada para relacionar a versão correspondente do código financeiro.

Trecho da consulta:
from test t
inner join sample s
    on s.sample_number = t.sample_number

inner join orders o
    on o.order_num = TBL2.order_num

LEFT JOIN FINANCE_CODE BFC
    ON BFC.NAME = TBL2.cost_code

INNER JOIN VERSIONS V
    ON V.TABLE_NAME = 'FINANCE_CODE'
    AND V.NAME = BFC.NAME
    AND V.VERSION = BFC.VERSION

7. Consolidação de diferentes cenários com UNION ALL

A View possui dois grandes blocos de dados. O primeiro trata pedidos aceitos e o segundo trata pedidos que ainda não foram aceitos. O UNION ALL reúne os resultados em uma única estrutura.

Trecho da consulta:
SELECT ...
FROM ...

UNION ALL

SELECT ...
FROM (...) TBL ...

8. Agrupamento dos resultados

O GROUP BY consolida os registros do primeiro bloco, agrupando pedido, amostra, status, plano de réplicas, laboratório e código de custo.

Trecho da consulta:
group by
    ORDER_NUM,
    SAMPLE_ID,
    STATUS_SAMPLE,
    REP_PLAN,
    LAB,
    COST_CODE

9. Pedidos não aceitos

O segundo bloco da View é identificado pelo comentário NOT ACCEPTED ORDERS. Ele considera pedidos cujo status agregado ainda não está entre os estados finais ou de exceção definidos na regra.

Trecho da consulta:
--NOT ACCEPTED ORDERS--

where O.aggregated_status not in (
    'ACCEPTED',
    'CLOSED',
    'CANCELED',
    'CANCELLED',
    'NOT SUBMITTED',
    'LT_PENDING',
    'ST_PENDING',
    'BIF_ERROR'
)

10. Tratamento dos diferentes cenários de planejamento

Dentro do bloco de pedidos não aceitos, o planejamento é formado por vários UNION ALL. São tratados cenários de análises individuais, listas de testes, análises individuais filhas, listas de testes filhas e conjuntos de amostras.

Exemplo dos blocos de planejamento:
select LT.ORDERS,
       LT.ID,
       LT.SAMPLES_COUNT,
       LT.PLANNED_RECEIPT_DATE,
       To_number(IA.NUM_REP) as NUM_REP,
       IA.COD_CUSTOS,
       IA.TIPO_CUSTO,
       IA.LAB
  from X_LT_PLANNING LT
  LEFT JOIN (TABLE(str2tbl(LT.INDIVIDUAL_ANALYSIS))) c
    on LT.INDIVIDUAL_ANALYSIS like '%' ||c.column_value || '%'
  LEFT JOIN plan_individual_analysis IA
    ON IA.LIMS_CODE = c.column_value
 WHERE LT.SAMPLES_SET IS NULL
   AND LT.INDIVIDUAL_ANALYSIS IS NOT NULL

UNION ALL

select LT.ORDERS,
       LT.ID,
       LT.SAMPLES_COUNT,
       LT.PLANNED_RECEIPT_DATE,
       To_number(BPTL.NUM_REP) as NUM_REP,
       BPTL.COD_CUSTOS,
       BPTL.TIPO_CUSTO,
       BPTL.LAB
  from X_LT_PLANNING LT
  left join(TABLE(str2tbl(LT.TEST_LIST))) c
    on LT.TEST_LIST like '%' || c.column_value || '%'
  LEFT JOIN PLAN_TEST_LISTS BPTL
    ON BPTL.TEST_LIST = c.column_value
 WHERE LT.SAMPLES_SET IS NULL
   AND LT.TEST_LIST IS NOT NULL

11. Contagem de conjuntos de amostras

Para determinados cenários filhos, a consulta calcula a quantidade de conjuntos de amostras utilizando COUNT(X_SAMPLES_SET), considerando somente registros marcados como filhos.

Trecho da consulta:
(SELECT COUNT(X_SAMPLES_SET)
   FROM X_SAMPLES_SET_CONFIG
  WHERE IS_CHILD = 'T'
    AND X_SAMPLES_SET = LT.SAMPLES_SET) AS SAMPLES_COUNT

12. Consolidação dos custos

Os custos são obtidos a partir da tabela financeira e disponibilizados separadamente por tipo. A View retorna custo fixo, variável, de mão de obra e o custo total.

Trecho da consulta:
BFC.FIXED_COST AS fixed_cost,
BFC.VARIABLE_COST AS variable_cost,
BFC.LABOR_COST AS labor_cost,
BFC.TOTAL_COST AS total_cost

13. Relacionamento com VERSIONS

O relacionamento com VERSIONS garante que o código financeiro seja associado à sua versão correspondente, considerando a tabela FINANCE_CODE.

Trecho da consulta:
INNER JOIN VERSIONS V
    ON V.TABLE_NAME = 'FINANCE_CODE'
    AND V.NAME = BFC.NAME
    AND V.VERSION = BFC.VERSION

Resultado

O desenvolvimento da View criou uma estrutura única para consolidar informações que estavam distribuídas em diferentes tabelas.

  • Centralização das informações utilizadas na análise;
  • Padronização do tratamento dos diferentes cenários;
  • Relacionamento entre informações operacionais e financeiras;
  • Reutilização da consulta em análises e relatórios;
  • Maior facilidade para análises de custos e planejamento.
A View transforma uma consulta complexa em uma fonte de dados estruturada e reutilizável, facilitando a utilização das informações em análises posteriores.

Consulta SQL completa

Abaixo está a consulta completa utilizada para construção da View ANALYTICAL_COST_PLAN_QUOTE.

CREATE OR REPLACE VIEW ANALYTICAL_COST_PLAN_QUOTE AS
select case when o.about_entity is null then replace(replace(REPLACE(o.project_code,CHR(9),'_'),chr(13),''),';','_') else o.about_entity end as project_code,
       o.template as programa,
       replace(replace(replace(REPLACE(o.project_name,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as project,
       replace(replace(replace(REPLACE(o.subproject_name,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as subproject,
       o.order_num as request_id,
       replace(replace(replace(REPLACE(o.technology_innovation,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as PIT,
       (select full_name from lims_users where user_name = o.created_by) as solicitante,
       (select full_name from lims_users where user_name = o.requester_2) as client_1,
       (select full_name from lims_users where user_name = o.requester_3) as client_2,
       TBL2.SAMPLE_ID as sample_id,
       TBL2.STATUS_SAMPLE as status_sample,
       (select analysis from test where cost_code = tbl2.cost_code and sample_number = TBL2.SAMPLE_ID and rownum = 1) as analysis_code,
       (select sc_en_rep_name from analysis where name = (select analysis from test where cost_code = tbl2.cost_code and sample_number = TBL2.SAMPLE_ID and rownum = 1) and rownum = 1) as analysis,
       to_date(o.received_on,'dd/mm/yy') as receipt_date,
       TBL2.REP_PLAN as rep_plan,
       TBL2.lab,
       TBL2.cost_code || ' - ' ||
       (select fc.description_en
          from finance_code fc INNER JOIN VERSIONS V ON FC.NAME=V.NAME AND FC.VERSION=V.VERSION
         where fc.name = TBL2.COST_CODE
           AND V.TABLE_NAME='FINANCE_CODE'
           and rownum = 1) as cost_code,
       BFC.FIXED_COST AS fixed_cost,
       BFC.VARIABLE_COST AS variable_cost,
       BFC.LABOR_COST AS labor_cost,
       BFC.TOTAL_COST AS total_cost
  from
(select * from
(select
       S.ORDER_NUM,
       s.sample_number as sample_id,
       (select EN_VALUE
          from list_entry
         where list = 'SAMPLE_STATUS'
           AND NAME = s.status) as status_sample,
       (select max(count(distinct(replicate_count)))
              from result
             where test_number = t.test_number
               and status in ('N','E','M')
            group by name) as rep_plan,
       t.lab,
       t.cost_code as cost_code
       from test t
 inner join sample s on s.sample_number = t.sample_number
 where t.cost_code is not null
   AND T.STATUS in ('I','P','C')) TBL
 group by ORDER_NUM,SAMPLE_ID,STATUS_SAMPLE,REP_PLAN,LAB,COST_CODE) TBL2
 inner join orders o on o.order_num = TBL2.order_num
 LEFT JOIN FINANCE_CODE BFC ON BFC.NAME = TBL2.cost_code
 INNER JOIN VERSIONS V ON V.TABLE_NAME = 'FINANCE_CODE' AND V.NAME = BFC.NAME AND V.VERSION = BFC.VERSION

UNION ALL

--NOT ACCEPTED ORDERS--
select case
         when o.about_entity is null then replace(replace(REPLACE(o.project_code,CHR(9),'_'),chr(13),''),';','_')
         else o.about_entity
       end as project_code,
       o.template as programa,
       replace(replace(replace(REPLACE(o.project_name,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as project,
       replace(replace(replace(REPLACE(o.subproject_name,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as subproject,
       o.order_num as request_id,
       replace(replace(replace(REPLACE(o.technology_innovation,CHR(9),'_'),chr(13),''),chr(34),''),';','_') as PIT,
       (select full_name from lims_users where user_name = o.created_by) as solicitante,
       (select full_name from lims_users where user_name = o.requester_2) as client_1,
       (select full_name from lims_users where user_name = o.requester_3) as client_2,
       TBL.ID as sample_id,
       O.AGGREGATED_STATUS as status_sample,
       (select analysis from test where cost_code = tbl.cod_custos and sample_number = TBL.ID and rownum = 1) as analysis_code,
       (select sc_en_rep_name from analysis where name = (select analysis from test where cost_code = tbl.cod_custos and sample_number = TBL.ID and rownum = 1) and rownum = 1) as analysis,
       TO_DATE(o.sample_receipt_date,'DD/MM/YYYY HH24:MI:SS') as receipt_date,
       tbl.num_rep * TBL.SAMPLES_COUNT as rep_plan,
       tbl.lab,
       tbl.cod_custos || ' - ' ||
       (select fc.description_en from finance_code fc where fc.name = tbl.cod_custos and rownum = 1) as cost_code,
       BFC.FIXED_COST as fixed_cost,
       BFC.VARIABLE_COST as variable_cost,
       BFC.LABOR_COST as labor_cost,

       LT.ID,
       (SELECT COUNT(X_SAMPLES_SET)

       To_number(IA.NUM_REP) as NUM_REP,
       IA.COD_CUSTOS,
       IA.TIPO_CUSTO,

  left join(TABLE(str2tbl(LT.INDIVIDUAL_ANALYSIS_CHILD))) c on LT.INDIVIDUAL_ANALYSIS like '%' ||c.column_value || '%'
  LEFT JOIN plan_individual_analysis IA ON IA.LIMS_CODE = c.column_value
 WHERE LT.SAMPLES_SET IS NOT NULL
   AND LT.INDIVIDUAL_ANALYSIS_CHILD IS NOT NULL

select LT.ORDERS,
       LT.ID,
       (SELECT COUNT(X_SAMPLES_SET)
          FROM X_SAMPLES_SET_CONFIG
         WHERE IS_CHILD = 'T'
           AND X_SAMPLES_SET = LT.SAMPLES_SET) AS SAMPLES_COUNT,
       LT.PLANNED_RECEIPT_DATE,
       To_number(BPTL.NUM_REP) as NUM_REP,
       BPTL.COD_CUSTOS,
       BPTL.TIPO_CUSTO,
       BPTL.LAB
  from X_LT_PLANNING LT
  left join(TABLE(str2tbl(LT.TEST_LIST_CHILD))) c on LT.TEST_LIST like '%' ||c.column_value || '%'
  LEFT JOIN PLAN_TEST_LISTS BPTL ON BPTL.TEST_LIST = c.column_value
 WHERE LT.SAMPLES_SET IS NOT NULL
   AND LT.TEST_LIST_CHILD IS NOT NULL
   ) TBL2 group by orders, id, samples_count,PLANNED_RECEIPT_DATE, num_rep, COD_CUSTOS, TIPO_CUSTO, LAB

   ) TBL inner join orders o on o.order_num = TBL.ORDERS
